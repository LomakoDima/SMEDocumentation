# Modernization: implementation and visual verification

## Background source

`src/components/HalftoneFlow.tsx` extracts the WebGL foundation from the user-supplied `halftone-flow-hero.tsx` in the project’s `prompt.txt`. The domain-warped flow function, 30-degree cell rotation, intensity-based dot sizes, and pointer bloom come from that source. The palette is adapted to black, burnt orange and warm orange. The original SaaS form, typewriter, proof/avatars and embedded font are excluded.

The canvas fills the hero background. A directional scrim protects readable text and CTAs. A CSS halftone fallback remains available during startup, failed WebGL setup or context loss. No image or engine UI is generated by this shader.

## Runtime behavior

- One fullscreen triangle, no rendering dependency, no per-frame layout measurement.
- Maximum 30 rendered frames per second, DPR capped at 1.5 and a 1.8 million pixel budget.
- Animation stops when the hero is offscreen, the document is hidden, the visitor requests reduced motion, or the visitor presses Pause motion.
- Reduced motion renders a still frame. Preference changes are handled live.
- Lost contexts use the static fallback and rebuild after restoration. Cleanup removes observers/listeners, deletes GPU resources and releases the context.
- The background is decorative and hidden from assistive technology. The site remains usable before hydration and without WebGL.

## Browser evidence

- Real WebGL context confirmed in the browser: `data-renderer="webgl"`, animation running, no shader/console errors.
- Two actual viewport screenshots were compared in the unobstructed shader region `(800, 160)–(1380, 620)`: 226,011 of 266,800 pixels changed by more than 5 levels (about 85%). This verifies changing rendered pixels, rather than merely the presence of a canvas.
- After Pause motion, two later screenshots of the same region were identical: mean RGB difference `[0, 0, 0]`. Resume motion restarted rendering.
- Scrolling past the hero changed its animation state to paused. The floating header remained visible, changing from a 20px top gap / 74px outer height to a 12px gap / 66px outer height on desktop.
- Desktop 1440px and mobile 390px layouts reviewed in-browser; header, text, CTA, authentic images, menu and scroll states inspected. Additional 320px width check performed.
- Mobile menu preserves all routes and GitHub, supports Escape with focus return, closes on selection/outside click and closes when resizing to desktop.
